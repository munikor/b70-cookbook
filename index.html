The launch command

docker run -d --name swift-tp2 \
  --device /dev/dri \
  --group-add 105 \
  --security-opt seccomp=unconfined \
  --security-opt label=disable \
  --ipc=host --shm-size 32g \
  -p 8220:8000 \
  -v /models/swift-15-int4:/models/swift-15-int4:ro \
  -v /models/vllm-cache:/root/.cache/vllm \
  -e NEOReadDebugKeys=1 \
  -e EnableDeferBacking=0 \
  -e CCL_SYCL_ALLREDUCE_LL=twoshots \
  -e CCL_SYCL_ALLREDUCE_SIMPLE_READ=1 \
  -e CCL_SYCL_COPY_ENGINE=1 \
  -e CCL_SYCL_ALLREDUCE_SIMPLE_THRESHOLD=4294967296 \
  -e CCL_SYCL_REDUCE_SCATTER_SIMPLE_THRESHOLD=4294967296 \
  -e CCL_SYCL_ALLGATHERV_SIMPLE_THRESHOLD=4294967296 \
  -e CCL_SYCL_ALLTOALL_TMP_BUF=1 \
  --entrypoint vllm \
  intel/llm-scaler-vllm:0.31.0-b1-experimental \
  serve /models/swift-15-int4 \
    --tensor-parallel-size 2 \
    --max-model-len 131072 \
    --gpu-memory-utilization 0.92 \
    --kv-cache-dtype fp8 \
    --max-num-seqs 8 \
    --max-num-batched-tokens 4224 \
    --speculative-config '{"method":"mtp","num_speculative_tokens":6}' \
    --compilation-config '{"cudagraph_mode":"FULL_DECODE_ONLY"}' \
    --enable-auto-tool-choice \
    --tool-call-parser qwen3_coder \
    --port 8000

Agent-workload note: the last two flags are what let tool-calling frameworks (TradingAgents, LangChain agent graphs, OpenAI-SDK tool use) hit this endpoint — without them every tool round-trip returns HTTP 400 "auto" tool choice requires --enable-auto-tool-choice. The parser for Swift/Qwen3.8-family checkpoints is qwen3_coder.

Five pitfalls that cost us hours (so they cost you zero)

  1. OneCCL allreduce dead at boot on the xe driver + kernel 7.2.11 — zeMemOpenIpcHandle → ZE_RESULT_ERROR_INVALID_ARGUMENT, every transport. Fix: NEOReadDebugKeys=1 -e EnableDeferBacking=0. With =1 it loads, computes, and wedges the box 12 minutes later. Non-negotiable.
  2. TTM eviction at high VRAM occupancy — any process touching a card while the pool rides ~97% triggers a 240-second driver hang, full box. Hard cap: --gpu-memory-utilization 0.92, no monitoring queries against the cards (XPU-Provider excluded — rocm-smi is a no-op there, verified clean).
  3. Missing --group-add 105 — the render-group GID on Fedora. Without it: oneCCL init fails with a cryptic device_fd is invalid.
  4. Community image TP2 IPC — the cyspiegel build's TP2 dies on the same IPC wall even with the fix applied (userspace mismatch). It runs TP=1 beautifully (we measured 84 t/s on one card). For TP2: Intel's official image. Use each build where it's proven.
  5. 5.7 GiB of VRAM in a profile pool nobody asked for — CUDA-graph memory profiling is on by default since v0.21.0; that pool is yours for KV.

What INT4 buys, in one paragraph

Not raw C1 speed — the drafter buys that. INT4 buys 4× the context (1M-token KV pool where BF16 had 131K), 4× the headroom (8 GiB/card free for co-residency vs 0.8), and a faster cold load (7 s vs 94 s). Quality: GPTQ-baked head + MTP linears, INT8 embeddings; the bake's withheld-activation checks show GPTQ halving round-to-nearest error on every baked linear. Our 10-probe math battery ran 9/10 exact on the quantized lane.
